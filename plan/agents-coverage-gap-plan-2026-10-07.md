# Agent coverage gap plan (7 October 2026)

*Status: proposed. A companion to `plan/agents-section-uplift-plan-2026-10-05.md`: it builds on that plan's tasks and lands
inside its phases.*

## 1. Why this plan

The question was whether the course covers every aspect of agents: the agent loop, multi-agent systems, and what
surrounds them.

**How it was checked.** A 63-aspect checklist was built: 21 aspects of the agent loop, 16 of multi-agent
systems and 26 cross-cutting, 39 of them must-haves. Its sources were:
- Anthropic's "Building effective agents" and "Writing effective tools for agents";
- Google's ADK and Gemini function-calling documentation, and the Google/Kaggle agents intensive;
- the LangGraph and LangChain documentation, and the A2A protocol;
- the MAST taxonomy of multi-agent failures;
- the Hugging Face and Microsoft agent courses, and the course's earlier 30-topic benchmark.

Every aspect was checked against today's lessons, the uplift plan and the corrected course structure, and every gap
was re-checked independently.

**What it found:**
- **Today:** 23 of the 63 aspects are taught hands-on.
- **After the uplift plan and the corrected structure:** 37 would be covered, 23 partial and 3 missing.
- **The weak area is multi-agent:** only 6 of its 16 aspects end up covered.
- **Several slots are names only.** ReAct, plan-and-execute, the Ralph loop, deadlocks, mixture of agents and
  human evals appear in the corrected structure with no content behind them.

**What this plan does:**
- It closes all 26 remaining gaps with 45 tasks in five clusters: N (loop mechanics and tools), P
  (reasoning, planning and coding agents), Q (multi-agent architectures), R (multi-agent boundaries and reliability)
  and S (evaluation, operations, safety and governance). One nice-to-have, MULTI-15, closes for cross-organisation
  agents only: its cross-cloud half waits, because the course stays on one cloud for now.
- It defines every agent lesson slot, 35 in all, so that none is a bare name. Five tasks (S10-S14) exist only
  to fill slots and close no gap.
- It lists the changes it makes to the uplift plan (section 4), which its first pull request applies once approved.
- Appendix A shows all 63 aspects before and after; appendix B shows how each gap closes.

### What a learner will be able to do afterwards

On their own lane, they will be able to:
- **write the loop by hand** on the Gemini SDK, and see exactly what each framework adds on top;
- **keep a conversation valid** across tool calls: every call answered, and thought signatures returned unchanged;
- **choose a reasoning pattern by measurement:** ReAct prompting against native thinking, plan-and-execute against
  plan-once, and reflection and best-of-n against a single attempt;
- **build and compare multi-agent architectures on the same questions:** router, supervisor, swarm, one agent and
  no agent, with handoffs, fan-out and shared state handled safely;
- **choose the boundary** between a function, a sub-agent, an MCP tool and an A2A agent, and **stop** cycles,
  livelock and deadlock;
- **diagnose a multi-agent failure from its traces** with a failure taxonomy, and score live agent traffic;
- **run a coding agent in a sandbox** that stops when the tests pass;
- **operate an agent lane:** let an agent propose one reversible fix that a person runs, and reproduce the failures
  production shows and no eval row does;
- **validate judges against people, size capacity, and threat-model and govern agents**, in English, Hindi and
  Hinglish.

### Size

45 tasks. Task sizes add up to 227 author-days, or 270–340 with rehearsal and capture, on top of
the uplift plan. 25 new pull requests; the rest fold into the uplift's own pull requests for the same lessons.

## 8. How this plan was made and checked

- **The register.** The coverage check's 63 aspects, with today's state, the uplift tasks that touch each, its
  slot in the corrected structure, the verified gap and a suggested fix.
- **Design.** Five designers, one per cluster, each read the lessons, the kit and the uplift tasks their aspects touch.
  They designed the smallest set of tasks that makes each aspect covered as it is stated, building on the uplift's
  tasks without duplicating them.
- **Critique and reconciliation.** A critic per cluster judged each aspect covered, partial or missing under the
  designs, and checked that files, functions, library APIs and uplift task ids exist. A reconciler then patched the
  tasks and added new ones until every aspect closed.
- **Slots and sequence.** A slot definer gave every agent lesson slot its content and proof, and marked any slot
  still thin. A sequencer placed every task in an uplift phase and a pull request.
- **Final review.** A last pass re-checked each of the 26 gaps against the finished tasks: 11
  closed as written, and 15 needed an amendment, now in the tasks file. It defined the four slots that were
  still thin or empty, which added tasks S10-S14. It also checked the plan's consistency: ids, ordering, Google and
  library facts against the pinned wheels, CLAUDE.md's rules and the uplift's decisions. Its 35 findings are applied to
  the plan's data, not listed as errata.
- **Checks.** A script confirms that every gap closes on a task that exists, every task has a place in a phase, every
  pull request names existing tasks and lists only tasks placed in it, no new pull requests wait on each other in a
  cycle, and every correction from the final review found the text it replaces.
