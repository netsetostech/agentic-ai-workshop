Live Session: from bytes to rows

Ninety minutes of reading the ingest code with the room, function by function, and running the pure ones as we go: the message contract, the parser and its page count, the shared PII scan, the chunker in both its homes, the embedding call with its carry-over. One clause of the ACME handbook rides through all of it.

Session goal

By the end, every learner can open services/ingest/ and say, for each of six files, what goes in, what comes out and which number inside it they would change in production. They have seen the chunker mint 283 chunks for both revisions of the handbook and the carry-over plan pay for two. And they can explain, from the code, why a vector without a task-type stamp is never reused.

  • A Colab notebook (or a laptop kernel) with the learner repo cloned and pydantic and pypdf installed; the lesson notebook GCP_Capstone_3.3_Bytes_To_Rows.ipynb run up to the sparse cell, so the outputs are on screen before anyone asks.
  • The kit open in an editor with six tabs: contracts.py, parser.py, shared/pii.py, shared/documind_corpus.py, main.py at _chunk, indexer.py.
  • Cloud Shell on a deployed lane (Module 2) with PROJECT, TENANT=acme, REGION exported and cd code done - only for the optional last demo.
  • The log filter ready in a tab: resource.labels.service_name="documind-ingest" AND jsonPayload.event="ingest_ok".
  • Both handbook revisions open side by side at NP-03: evals/corpus/acme/hr_policy_2026.md and evals/demo/hr_policy_2026_v2.md.

If it breaks

ModuleNotFoundError: No module named 'contracts' (or 'shared')

The kit root or services/ingest is not on sys.path. The notebook's third cell adds both; re-run it and print sys.path[:3]. On a laptop, run from the kit root with PYTHONPATH=.:services/ingest. If the error names indexer or main, somebody imported the worker: those two files build cloud clients at import and are meant to be read, not imported - copy the function.

The embedding cell fails: 404 NOT_FOUND, or PERMISSION_DENIED

A 404 on the model almost always means the client was built with location="global": embeddings are regional, and the kit's client says us-central1. A permission or authentication error means the auth cell did not run (Colab), Application Default Credentials are missing (gcloud auth application-default login), or the Vertex AI API is not enabled. Do not switch to an API key. If it still fails, skip the cell - it is the only one that costs money and nothing later depends on it.

load_documents finds no documents, or a mirror is missing

load_documents needs evals/manifest.json and the .md mirrors beside the PDFs. An empty list means the evals_dir path is wrong: print it. A real Act without its mirror means an incomplete clone or a kit whose fetch_real.py never ran; the learner repo ships the mirrors, so re-clone with --depth 1 rather than fetching from the ministry during a session. The scanned POSH Act has no mirror by design and is skipped.

Discussion prompts

  1. The doc_key is the hash of the bytes. A colleague proposes hashing the text after parsing, so a re-saved PDF with identical text is a duplicate. What do you gain, what do you lose, and what does it do to the free page count?
  2. EMBED_TOKENS is 15,000 against a 20,000 limit, at 3 characters a token. Which document in the corpus would you test the estimate on, and what would you change if a request failed?
  3. The findings record holds the type and the offset, never the value. Which team in your company would ask for the value, and what do you answer?
  4. The chunker is duplicated in two files and held together by a gate. Would you rather have one file imported by both? What stops the notebooks from importing main.py?
  5. The worker's rows say doc_type: unknown for every text document while the notebook's seed writes policy or statute. Where would you set the type on the lane - the object name, a metadata header, the manifest - and what would it do to the restricts?
