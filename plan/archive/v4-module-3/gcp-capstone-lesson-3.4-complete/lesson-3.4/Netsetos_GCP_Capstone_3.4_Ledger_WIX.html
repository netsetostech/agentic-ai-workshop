Step 2 of 9

The claim: one worker per version, in a transaction

claim(), the retake rule, finish() and release(), and the failure release() fixed.

A claim is a row in documents/ whose id is the version's doc_key, acme_<sha256>. Whoever writes it first owns the version. The function is one transaction, and its docstring says why: read-then-write without one is a race with a window of milliseconds, and Pub/Sub delivers duplicates concurrently, so it is a window that gets hit.

services/ingest/idempotency.py - claim(), docstring cut
def claim(db: firestore.Client, doc_key: str, gcs_uri: str, tenant_id: str, retake: bool = False) -> bool:
    # ...
    ref = db.collection("documents").document(doc_key)
    retakes = ("failed", "superseded") if retake else ("failed",)

    @firestore.transactional
    def _claim(tx: firestore.Transaction) -> bool:
        snap = ref.get(transaction=tx)
        # A claim that ended in `failed` is not a claim, it is a record of one. release()
        # writes it so the error is readable; the NEXT delivery must be allowed to try
        # again, or "give the claim back" gave nothing back: on the first live load every
        # retry of a failed document was acked as a duplicate and the document stayed failed.
        if snap.exists and snap.get("status") not in retakes:
            return False
        tx.set(ref, {"gcs_uri": gcs_uri,
                     "tenant_id": tenant_id,
                     "status": "processing",
                     "claimed_at": firestore.SERVER_TIMESTAMP})
        return True

    won = _claim(db.transaction())
    if not won:
        log.info('{"event":"ingest_duplicate","doc_key":"%s"}', doc_key)
    return won

Three details carry weight. The row stores tenant_id as a field, because the MCP server's list_documents filters on the field, never on the id's prefix - acme must not list acme_eu_*. The retake rule: failed may always be retaken, superseded only with retake=True (step 6 shows who passes it), queued never. And a refused claim logs ingest_duplicate here, before push() knows whether it is a duplicate, an undo or a queued document - that line comes first in step 9.

🚇

The railway reservation counter. Two clerks at two stations both see berth 42 free. If each sells it from what they saw a second ago, two passengers hold one berth. The reservation system makes the read and the write one booking, so the second booking fails with the berth taken. claim() is that booking: the version is the berth, and the transaction is what makes the second worker lose instead of both winning.

The comment inside claim() tells the second half: an early version treated failed like any other claim, so every retry of a failed document was acked as a duplicate. The fix is one line - a claim that ended in failed is not a claim, it is a record of one.

Step 3 of 9

The guard: an older generation is a late redelivery

stale_generation() against the ledger row, the pure rule in contracts.py, the download by generation.

Cloud Storage numbers every version of an object; the number is its generation, and it only grows. The ledger row for a path records the generation it indexed. Push delivery is at-least-once and not in order, so the event for an older generation can arrive after a newer one has been indexed, and acting on it would make the old version current again. The guard reads the ledger row before anything is downloaded.

services/ingest/idempotency.py - stale_generation(), docstring cut
def stale_generation(db: firestore.Client, tenant_id: str, name: str, generation) -> str | None:
    # ...
    snap = db.collection("sources").document(source_id_for(tenant_id, name)).get()
    row = (snap.to_dict() or {}) if snap.exists else {}
    have = row.get("generation")
    try:
        if have and int(str(generation)) < int(str(have)):
            return str(have)
    except (TypeError, ValueError):
        return None
    return None

Step 4 of 9

current_chunks: the version the other lane already wrote

Why a won claim is not yet a reason to parse, and what a row must carry to count.

The worker is not the only writer of chunks/. The Module 4 notebooks seed the same collection through shared/documind_corpus.seed(): the same doc_key for the same bytes - a real Act's is the sha of its PDF, never of its Markdown mirror - and the same ledger row, but never the claim. So when that PDF is uploaded to the bucket, the worker wins claim() for a version whose rows are already current. current_chunks() is the question push() asks before it parses anything.

services/ingest/idempotency.py - current_chunks(), docstring cut
def current_chunks(db: firestore.Client, tenant_id: str, gcs_uri: str, doc_key: str,
                   embedding_model: str | None = None, embedding_version: str | None = None) -> int:
    # ...
    n = 0
    query = (db.collection("chunks").where("tenant_id", "==", tenant_id)
             .where("source_uri", "==", gcs_uri).where("current", "==", True))
    for snap in query.stream():
        if _doc_key_of(snap) != doc_key:
            continue
        d = snap.to_dict() or {}
        if embedding_model and (d.get("embedding_model") != embedding_model
                                or str(d.get("embedding_version")) != str(embedding_version)
                                or d.get("embedding_task_type") != "RETRIEVAL_DOCUMENT"):
            continue
        n += 1
    return n

The count is strict on purpose. A row counts only when it is current, belongs to this doc_key (_doc_key_of, line 108, turns a pre-ledger id tenant:sha256#i into the key), and carries the same embedding_model, embedding_version and the task type RETRIEVAL_DOCUMENT. A row without the stamp could not serve this worker's queries, so it does not count, and the ingest proceeds as a fresh version whose carry-over reuses nothing from it.

What just happened

With a non-zero count (main.py 401-414) nothing is parsed or embedded. The claim becomes its record with the rows it already holds, the ledger learns this generation so the walk stops planning a re-ingest, the fingerprint is refreshed, and ingest_already_current says what was found: reused equal to the count, embedded: 0, seeded_by the generation the ledger held before. The other order needs nothing - seed() skips a version the lane already holds current.

Step 5 of 9

The swap: new rows first, old rows retired, never deleted

swap_versions() and _retire(), the two-commit window, and retire_previous() with no version to keep.

Lesson 3.3 read mirror_to_firestore(), which writes a new version's rows with current: False, staged: True and a one-day expire_at (STAGE_HOURS = 24 in main.py), so a stage nothing ever swaps leaves by the same policy that removes a retired row. No reader can see a staged row. The swap is the one pass that makes the version visible, and its order is the whole design.

services/ingest/idempotency.py - _retire(), swap_versions(), docstring cut
def _retire(batch_state: list, snap, keep_doc_key, expire_at, effective_to) -> None:
    fields = {"current": False, "superseded_by": keep_doc_key, "superseded_at": firestore.SERVER_TIMESTAMP}
    if expire_at is not None:
        fields["expire_at"] = expire_at            # the TTL policy's field: the platform deletes the row after it
    if effective_to:
        fields["effective_to"] = effective_to      # the successor's effective date closes this version's window
    batch_state[0].update(snap.reference, fields)
# ...
def swap_versions(db: firestore.Client, tenant_id: str, gcs_uri: str, new_doc_key: str, expire_at=None,
                  effective_to: str | None = None, chunks_collection: str = "chunks") -> dict:
    # ...
    activated, retired_keys, retired_ids = 0, set(), []
    state, pending = [db.batch()], 0
    query = (db.collection(chunks_collection).where("tenant_id", "==", tenant_id)
             .where("source_uri", "==", gcs_uri))
    rows = list(query.stream())
    for snap in rows:                                       # the new version first: a reader never finds no version
        d = snap.to_dict() or {}
        if _doc_key_of(snap) == new_doc_key and d.get("current") is not True:
            state[0].update(snap.reference, {"current": True, "staged": firestore.DELETE_FIELD,
                                             "expire_at": firestore.DELETE_FIELD,
                                             "superseded_by": firestore.DELETE_FIELD,
                                             "superseded_at": firestore.DELETE_FIELD,
                                             "effective_to": firestore.DELETE_FIELD})
            activated += 1
            pending += 1
            if pending == BATCH:
                state[0].commit()
                state, pending = [db.batch()], 0
    for snap in rows:                                       # then the old: a flag, never a delete
        d = snap.to_dict() or {}
        key = _doc_key_of(snap)
        if key == new_doc_key or d.get("current") is False:
            continue
        _retire(state, snap, new_doc_key, expire_at, effective_to)
        retired_keys.add(key)
        retired_ids.append(snap.id)
        pending += 1
        if pending == BATCH:
            state[0].commit()
            state, pending = [db.batch()], 0
    if pending:
        state[0].commit()
    for key in retired_keys:
        db.collection("documents").document(key).set(
            {"status": "superseded", "superseded_by": new_doc_key,
             "superseded_at": firestore.SERVER_TIMESTAMP,
             "retired_at": firestore.SERVER_TIMESTAMP}, merge=True)     # the undo window's clock (reactivate)
    return {"activated": activated, "retired_doc_keys": sorted(retired_keys), "retired_ids": retired_ids,
            "retired_chunks": len(retired_ids)}

Two loops, two halves of a promise. The first flips the new version's rows to current: True and deletes the stage marks and any leftover retirement fields. The second calls _retire() on every other current row of the source: current: False, superseded_by the new key, superseded_at, expire_at when the caller passed a retention (the worker passes now plus RETENTION_DAYS), effective_to when the successor declares a date. Both loops share one batch, committed every 400 writes. Then every retired version's claim is stamped superseded with retired_at - the clock the undo reads.

The window between two commits, and who hides it

Both loops count into one batch of 400, so a re-issue whose two versions total 400 rows or fewer flips in one commit (the docstring says "up to ~250 chunks"; counting the retired rows too, 200 is the safe figure). A longer document flips in two commits, and between them both versions are current. The reader closes that window: services/rag-api/retriever.py's prefer_current() drops every row with current: False, then newest_per_source() keeps one version per source_uri - the doc_key whose rows landed last by indexed_at or reactivated_at. Because the new rows were flipped first, a reader in the window gets the new version only.

retire_previous() (185-216) is the same retirement with nothing to keep: the same query, _retire(), batches and claim stamp. The difference is keep_doc_key. The worker's undo passes the reactivated key, so the newer version is retired and the reactivated one kept; the reconcile passes None - the object left the bucket, or a person withdrew it - and the whole source is retired. Two equality filters need no composite index, which is why neither function filters on current in the query.

Step 6 of 9

The undo: counted, dated, then flipped - and the ledger row

withdrawn() and reactivate(), the worker's undo branch, then record_source() and the fingerprint.

The undo is the same bytes uploaded again after a newer version retired them. Their rows are still in chunks/, flagged, so flipping the flag back is a re-index that costs nothing - because nothing was deleted. Two checks stand in front of the flip. The first is the tombstone, withdrawn() (273-277): a source a person took down with make retire is withdrawn in sources/, and only make restore brings it back. The worker asks before the undo; reactivate() asks again, so no caller can skip it.

The second check is the count and the clock, and the docstring records the failure behind them: the first undo flipped whatever rows remained and retired the newer version on the strength of it; after RETENTION_DAYS the TTL policy had taken the rows, zero were flipped, and the source was left with no current version at all.

def reactivate(db: firestore.Client, tenant_id: str, gcs_uri: str, doc_key: str,
               chunks_collection: str = "chunks", retention_days: int | None = None) -> int | None:
    # ...
    if withdrawn(db, tenant_id, gcs_uri):
        log.info('{"event":"reactivate_withdrawn","doc_key":"%s","gcs_uri":"%s","hint":"make restore SOURCE="}',
                 doc_key, gcs_uri)
        return None
    query = (db.collection(chunks_collection).where("tenant_id", "==", tenant_id)
             .where("source_uri", "==", gcs_uri))
    rows = [snap for snap in query.stream()
            if _doc_key_of(snap) == doc_key and (snap.to_dict() or {}).get("current") is False]
    claim_snap = db.collection("documents").document(doc_key).get()
    record = (claim_snap.to_dict() or {}) if claim_snap.exists else {}
    expected, stamp = record.get("chunks"), record.get("retired_at")
    window = RETENTION_DAYS if retention_days is None else int(retention_days)
    age = None
    if isinstance(stamp, datetime):                     # a claim from before the stamp has no clock: the count decides
        age = (datetime.now(timezone.utc) - (stamp if stamp.tzinfo else stamp.replace(tzinfo=timezone.utc))).days
    short = expected is not None and len(rows) < int(expected)
    if short or (age is not None and age > window):
        # ...
        return None
    n, batch, pending = 0, db.batch(), 0
    for snap in rows:
        batch.update(snap.reference, {"current": True, "superseded_by": firestore.DELETE_FIELD,
                                      "superseded_at": firestore.DELETE_FIELD,
                                      "expire_at": firestore.DELETE_FIELD,
                                      "effective_to": firestore.DELETE_FIELD,
                                      "reactivated_at": firestore.SERVER_TIMESTAMP})
        n += 1
        pending += 1
        if pending == BATCH:
            batch.commit()
            batch, pending = db.batch(), 0
    if pending:
        batch.commit()
    db.collection("documents").document(doc_key).set(
        {"status": "indexed", "superseded_by": firestore.DELETE_FIELD, "retired_at": firestore.DELETE_FIELD,
         "reactivated_at": firestore.SERVER_TIMESTAMP}, merge=True)
    return n

The retired rows still here are counted against the claim's chunks, and the claim's retired_at against the window. A shortfall or a closed window is reactivate_incomplete with both numbers on the line (310-313), None comes back, and nothing has changed. A claim from before the stamp has no clock, and the count alone decides. When both checks pass, every row is flipped with its retirement fields deleted and reactivated_at stamped, the claim returns to indexed with retired_at cleared, and the count comes back.

The bank passbook. A wrong entry is never erased. The bank adds a reversing entry, and the original line stays on the page with a note beside it: the balance is right, and an auditor sees both lines and the date of each. A retired chunk row is the original line, superseded_by and superseded_at are the note, and reactivate() is the reversing entry - written only after the teller has counted that every line of the original entry is still on the page.

The order inside the branch matters as much as the order inside the swap. After a successful reactivate(), the ANN tier is repaired first: reupsert() (indexer.py, read in 3.3) puts the reactivated ids back into Vector Search from the rows' own vectors before retire_previous() retires the newer version and remove_datapoints() takes its ids out, so a reader of the tier never finds none. Then the managed mirror follows (after_undo, 365), record_source() rewrites the ledger row with reused equal to the count and embedded: 0 (367-370), the fingerprint moves, and the line is ingest_reactivated. One honest footnote: embedded: 0 is the carry-over's number; reupsert() re-embeds a row only when its stamp no longer matches (_repair_snapshots), and that repair is not on this line. When reactivate() refuses, the worker takes the claim back with claim(retake=True) and falls through to index_document(): the carry-over reuses every vector the newer version still holds by chunk_hash, and the swap retires it only once the new rows are whole.

The ledger row is keyed by the object path with the slash swapped for a tilde (source_id_for: acme~hr_policy_2026.md), because a Firestore id cannot hold a slash. The fingerprint is the sha256 of the tenant's sorted current doc_keys, cut to sixteen characters: it changes on every reindex, retirement and reactivation and on nothing else. refresh_fingerprint() (365-375) writes it to ledger/{tenant} with the event that moved it; the API's cache manager compares it with its cache record and answers uncached on a mismatch (cache_stale). The record is never deleted here - the demo README's older wording, "drops ACME's cache record", describes what the API does with the mismatch, not what this function writes.

What just happened

The undo is verified before it is trusted, ordered so the ANN tier never goes empty, and recorded on the same three rows as any other ingest: the claim, the ledger row, the fingerprint. The one thing it does not do is call the embedding model. That is the sentence the module gate asks you to say out loud: the undo embedded nothing because the rows were flagged, not deleted, and the flag was flipped back only after the count and the clock agreed.

def decide_bytes(sha: str, tenant_id: str, ledger_row: dict | None, documents: dict[str, dict]) -> str:
    # ...
    key = f"{tenant_id}_{sha}"
    if ledger_row and ledger_row.get("sha256") == sha:
        return "touch"          # the bytes did not change: record the new generation, nothing to index
    status = documents.get(key, {}).get("status")
    if status in ("indexed", "superseded"):
        return "backfill"       # the version exists; the ledger just never heard of it
    if status == "queued":
        return "queued"         # the worker handed these bytes to the batch lane; a rewrite would only re-queue them
    return "reingest"
# ...
def drift_of(summary: dict) -> int:
    # ...
    return int(summary.get("retire", 0)) + int(summary.get("reingest", 0)) + int(summary.get("backfill", 0))

Three pure rules. decide_bytes() runs after an object has been hashed: the ledger's own sha is a touch (record the generation, index nothing); a sha the claims hold as indexed or superseded is a backfill; a queued claim is left to the batch job; anything else is a reingest, done by rewriting the object onto itself so the worker's one path handles it. drift_of() is the night's number - retire plus reingest plus backfill - and alerts.tf turns the reconcile_done line into documind/reconcile_drift, which pages when it stays above zero for two nights; a withdrawn source and a queued document are decisions, not drift. expired() is the manual twin of the TTL policy, what make purge prints and, with APPLY=1, deletes on a lane without the policy. The other flags map to targets one to one: --backfill --apply is make backfill-current, --report is make sources, --selftest runs the rules offline.

--retire (make retire SOURCE=) is retire_previous() with keep_doc_key=None, then the ledger row set to withdrawn - not retired, because retired means the object left the bucket and an object that is back is re-ingested; the first version of the walk resurrected what a person had just taken down. --restore (make restore SOURCE=) moves the tombstone to retired first, the state a lost event recovers from, then rewrites the object onto itself: a new generation, the same event, the worker's one path - ingest_reactivated inside the undo window, ingest_ok as a fresh version after it.

Three uploads of one object name produced two versions, six rows, three ledger states and one fingerprint that returned to where it started. The one rule to remember

Every function on this page writes a flag, a stamp or a count. None writes a delete. A version is claimed in a transaction, made visible in a swap, retired with a date, and brought back only after the rows and the clock have been counted. Keep that shape and an update costs what changed, is invisible until it is whole, and can be undone for free.
