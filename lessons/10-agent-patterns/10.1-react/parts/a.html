Choose where the agent reasons: observe-think-act and ReAct

Every agent runs one loop. It observes the question, its tools and every result so far; it thinks; it acts, by calling a tool or answering. Where the thinking happens is a choice, and the choice has a bill. Gemini thinks natively, in thinking tokens you pay for at the output price and never see, then calls a tool by function calling. Prompted ReAct, made for models with no function calling, has the model write its reasoning as text, Thought: and Action:, stops it at Observation:, and lets code read the Action, run it and write the result. A plan-first prompt asks for a numbered plan before the first call. You run all three on the agent bench, with the Desk agent's tools and its %%N_CALCS%% calculators: one turn offline and on your lane, then the %%N_CALC%% calculator rows, with correct answers, thinking and visible tokens, and rupees for each. Then you delete the one line of code that keeps a model's own Observation out, and watch an invented figure become the answer.

Level 0 · Theory

One loop, three places to reason

Observe, think, act; and where the thinking goes.

One loop. Every agent in the kit runs the same loop. The model observes: the question, the tools it may use and every result so far. It thinks. Then it acts: it calls a tool, or it answers. The tool's result is the next observation, and the loop goes round again. Lesson 5.1 built this loop on the chat brains, and lesson 5.4 drew it as a graph. Each pass is one model call, and each call reads the whole turn again, so a long turn pays for its early text many times over. The turn's limits from lesson 5.5 stop it at %%MAX_CALLS%% calls, Rs %%BUDGET%% or %%DEADLINE%% seconds.

Native thinking. Gemini 3 models think before they write. The thinking is spent in thinking tokens: you never see them, and you pay for them at the output price, USD %%RATE_OUT%% a million on %%MODEL%%, which is Rs %%RS_K_OUT%% for every 1,000. A request's thinking_level says how much to spend. The bench sends minimal, low, medium or high, and step 8 shows which of them your model takes on location global. Then the model acts by function calling: the request declares the tools, and the reply is a structured call, a name and JSON arguments, which the framework runs. The Desk agent sends %%DEFAULT_LEVEL%%. This is the bench's loop pattern.

Prompted ReAct. ReAct, reason and act, came first, for models with no function calling. No tool is declared. The tools are written into the prompt as text, with a protocol, and the model writes one step a reply: Thought:, what it needs and why, then Action: tool[{"argument": value}]. It stops at Observation:, a stop sequence the request sends. Code reads the Action, runs the tool and writes the Observation: line itself, and the next call sends the whole transcript again. The reasoning is now visible text, billed as output too, and a thinking model still thinks natively before it writes. This is react_text.

A plan first. The third pattern keeps the loop and puts one instruction at the top of its prompt: write a numbered plan before the first tool call. The plan is visible text, written once and read back on every later call. Nothing runs it: the loop still decides every call, and the model may leave its plan. Lesson 10.2's patterns execute their plans in code. This is plan_first.

The arithmetic is never the model's. All three run on the agent bench, commands/agent_patterns.py. It builds the Desk agent of lesson 10.4 beside the Desk's own, with a recorder added: one retrieve over the classes policy, statute and guidance, and the %%N_CALCS%% calculators of shared/desk_calc.py. The prompt tells every pattern to work each figure out with a calculator, and a calculator takes only numbers written in the question or in the right clause of a passage the turn read. Lesson 10.5 teaches that check. Here it means one thing: a right figure that no calculator returned is a figure the model worked out itself, and the eval says so.

What only code may write. In prompted ReAct the Observation belongs to code. A model that runs on past its Action and writes Observation: %%INVENT%% has invented a tool's result, and if anything reads it, the invention becomes the answer. Two things stop that. The stop sequence asks Gemini to end its reply before it writes Observation:. The parser's cut, the first line of read_step(), reads nothing from the first Observation: on, whatever the model wrote. Step 6 deletes the cut.

📋

Three chartered accountants work out the same client's gratuity. The first works it out in her head. You pay for her minutes, but all you see are her instructions to the article assistant, "fetch the Code, section 53", and the figure she signs. The second writes every step in the working papers: "Thought: I need section 53. Action: fetch section 53." The assistant fetches it and writes what he found underneath, "Observation: ...", and the file goes back to her desk, to be read from the top before the next step. Her firm has one rule for that file: only the assistant writes an Observation. If she writes "Observation: Rs 2,50,000" herself, the assistant tears off everything after her last Action before he files it. The third CA writes a plan on the file's cover first, "1. fetch section 53, 2. run the gratuity sheet, 3. sign", then works like the first, and nobody checks her against her plan. In all three offices the arithmetic is done on the firm's gratuity sheet, which accepts only numbers from the client's letter or from the Code.

For the gratuity row you can also choose what the stop sequence does: hold, as Gemini's should; fail to hold, with the parser's cut in place; or fail to hold with the cut deleted, which is step 6.

One question, three patterns - commands/agent_patterns.py, one model call at a time

Every call here is the kit's own turn, run when this page was built: each row's scripted model, the one make agent-turn OFFLINE=1 uses, over the kit's own corpus, so the three patterns search with the same words, call the same calculator with the same arguments and give the same answer. The token counts are the script's: four characters a token, and %%SCRIPT_TH%%. The loop's script counts no tool declarations, which Gemini does count on your lane, about %%DECL_TOKENS%% tokens a call; react_text carries its tools as text in its prompt, and the script counts them. Step 8 shows your lane's own counts.

What the panel is not

A scripted model never wavers. On your lane, Gemini chooses its searches and its calls, may write a different plan or none, and spends the thinking it chooses at each level. What does not change is who writes what: the thinking is the model's, an Observation is code's, and every figure is a calculator's.
