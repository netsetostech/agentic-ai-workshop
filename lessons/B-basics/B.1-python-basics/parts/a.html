Level 0 · Theory

What the kit's Python does, in three habits

An environment of its own, JSON in and out, HTTP between the parts, and what async adds to the third.

An environment of its own. Each of the kit's %%N_SERVICES%% services has a folder under services/, and in it a requirements.txt that names the libraries the service needs, each with == and one exact version: %%N_PIN_LINES%% lines across the %%N_SERVICES%% files, and not one of them without a version. %%N_SLIM%% of the services build their image from python:3.12-slim and install their file into it; the other %%N_OTHER_BASE%% start from a vendor's image (vLLM, LiteLLM and Ollama). Where two services use the same library they pin the same version, and the kit's dry run fails if they do not. On your laptop a virtual environment, a venv, does the image's job: a folder with its own Python and its own libraries, so that what one project installs cannot break another.

JSON in and out. A question to the DocuMind API is a JSON object, and so is its answer. The golden set the eval gate runs is a file of JSON objects, one per line, and every usage row the API writes to its log is a JSON object that Cloud Logging turns into fields. Python's json module does both directions: json.dumps() turns a dict into text, and json.loads() turns the text back into a dict.

HTTP between the parts. The UI, the chat service, the smoke test and the eval gate all reach the API the same way: an HTTP request to a URL, with an ID token in the Authorization header and, for a question, a JSON body; back comes a status code and a JSON body. A call like that spends most of its time waiting for the other side, and async is how one program waits on several calls at once instead of one after another.

🍱

A dabbawala's tiffin. Every morning in Mumbai a tiffin leaves a home with one person's lunch in it, packed in its own sealed tins, so that nobody's dal ends up in anybody else's rice. That is a venv: one project's libraries, at the versions it was tested with, in a box of their own. On the lid is a painted code that every dabbawala reads the same way, from the station to the office floor. That is JSON: a format both ends agree on, so what was packed in Andheri is read correctly at Churchgate. The tiffin goes out full and comes back empty in the afternoon: one request, one response, which is HTTP. And no dabbawala carries one tiffin at a time; he carries a crate of them on the same train and hands each one over as its stop comes. That is async: one worker, many deliveries in flight.

Pin explorer - every requirements.txt in the kit, and validate.py's two checks

A teal pin is pinned by at least one other file, and the number after it counts the files that pin that library. The page opens on rag-api's google-genai==%%GENAI_PIN%%, the version the setup block installs on your laptop. Type 2.20.0 in the version box and the pins check fails the way validate.py does, naming every file and its version. Tick the box instead and the requirements check warns. The requirements check reads the %%N_SERVICES%% service files; the pins check reads those and shared/requirements.txt, %%N_PIN_FILES%% files. The port was compared with validate.py itself on all %%N_CASES%% one-pin changes (every pin given another version, then none) when this page was built.

What the explorer is not

It reads the files and applies the two checks; it is not pip. It cannot tell you whether a version exists, or whether a set of versions can be installed together. pip answers those when an image is built, and the dry run builds every Python image with Docker when it runs in CI.

Level 1 · Definitions

The words: venv, site-packages, pin, JSON, JSONL, status code, token, event loop

Ten terms, each with where it shows up in the kit.

WordMeaningIn the kit
Virtual environment (venv)A folder with a Python of its own and a site-packages of its own, made by python -m venv. Activating it puts its Python first on PATH.~/basics-venv on your laptop. The services use images instead: %%N_SLIM%% of the %%N_SERVICES%% Dockerfiles start from python:3.12-slim.
site-packagesThe folder where pip installs libraries for one Python. A venv's is its own, so what is installed there is invisible to every other Python on the machine.numpy and google-genai, in ~/basics-venv's.
PinA requirement written name==version: exactly that version, never "the newest".%%N_PIN_LINES%% lines in %%N_SERVICES%% service files, every one pinned; google-genai==%%GENAI_PIN%% in %%N_GENAI%% of them.
pathlib.PathA path as an object: / joins parts, .open() opens the file to read or write, .read_text() reads it whole, .rglob() searches a folder tree.validate.py finds the requirements files with SERVICES.rglob("requirements.txt").
JSONText that writes objects, arrays, strings, numbers, true, false and null. json.dumps() writes it, json.loads() reads it.Every question and answer of the API, and every usage row it logs.
JSONLJSON Lines: one JSON value per line, so a file is written and read a row at a time.evals/golden.jsonl, %%N_GOLDEN%% rows; %%N_JSONL%% JSONL files in the kit, %%JSONL_LINES%% lines.
Status codeThe three-digit number a response starts with: 200 OK, 401 no credential, 403 not allowed, 404 no such path, 5xx the server failed.smoke.py wants a 200 for a question, and a 401 or 403 for the same question with no token.
ID tokenA short-lived token, signed by Google, that names the caller. It travels in the header Authorization: Bearer <token>, and Cloud Run checks it before the service's code runs.smoke.py asks gcloud for one; shared/documind_tools.py mints a new one for every call.
Coroutine, event loopA function written async def returns a coroutine. An event loop runs many coroutines in one thread, switching to another whenever one is waiting at an await.rag-api runs %%RAG_WORKERS%% uvicorn workers under gunicorn: %%RAG_WORKERS%% processes, an event loop in each.
gather, to_threadasyncio.gather() waits for several coroutines at once and returns their results in the order given. asyncio.to_thread() runs an ordinary blocking function in a thread, so the loop stays free.The chat service asks the roster in Firestore through asyncio.to_thread.
