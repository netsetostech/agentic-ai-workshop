Level 0 · Theory

Two ways to help a model answer: room to think, and solved examples

Chain of thought, native or prompted; few-shot against zero-shot; and why each is measured on the same rows with its interval.

Chain of thought is work written before the answer. A model writes one token at a time (lesson B.5), so whatever it writes before its answer is something the answer can build on. Golden row jn-03 asks "I am an E3 leaving with 50 days of earned leave. How much is encashed and what notice do I serve?" The answer needs two clauses and one step between them: the handbook's cap on leave encashment, the notice period for an E3, and the question's 50 days held against the cap. That is the bet chain of thought makes: a model that works those out first may get them right more often than one that starts writing the answer at once. Step 6 measures whether it does here. A Gemini 3 model does this natively: before its reply it writes thought tokens, billed at the output rate whether or not anyone reads them. thinking_level sets how much: MINIMAL, LOW, MEDIUM or HIGH. MEDIUM is gemini-3.6-flash's default (lesson B.5 reads Google's model page), and the kit's generator pins LOW. Its request names the level and nothing else, so the thoughts never come back to the kit: only their count does.

Prompted reasoning writes the working where the person reads it. Before models thought natively, the way to get a chain of thought was to ask for it in the prompt, "work it out step by step", and let the model write its working into the reply. You can still do that, and it is the one change step 7 makes. In DocuMind it has a cost the textbook version does not. The generator asks for a ModelDraft, four fields, and google-genai sends them to the model in a fixed order: answer, citations, confidence and answerable. None of them is for working. So working that the prompt asks for is written into answer, the text the Chat page shows. It is billed as visible output and counts toward rule 4's 300 words. Native thinking happens before the first field; prompted working happens inside it.

Few-shot shows the task instead of only describing it. A zero-shot prompt describes the task and its rules. A few-shot prompt also shows solved examples, each an input with the right output, and the model continues the pattern. The kit uses each where it fits. The generator's SYSTEM is zero-shot: five rules and no example, because every answer is different and so is every context. The router's first classifier, L1, is few-shot. It is gemini-3.1-flash-lite with a thinking budget of 0, an answer of five enum fields and no room to explain. It reads the desks, the rules and eight example questions, each labelled with its desk (desk_routes.PROMPT_EXEMPLARS, at most twelve). Choosing one label out of five suits examples: a small model that does not think can copy the boundary the examples draw, between a handbook question and a statute one, or between the company's own question and another system's. Lesson 10.4 builds the router; this lesson takes its examples out and puts them back.

Measure each on the same rows, with an interval. A technique that helps on the question you tried can hurt on the next one, so the kit measures every change over a set of rows and prints every rate with its Wilson interval. On the 11 join rows, 11 of 11 passing has the interval [74.1%, 100.0%]. Two levels' intervals stop overlapping only when their pass counts are at least six rows apart, and at that gap only at the two ends of the scale: all 11 against 5, or 6 against none. So one run per level settles little about accuracy, while the thought tokens and the rupees per answer show up at once. The router's L1 sees 126 turns a run, so its intervals are narrower. Both arms answer the same turns, so the turns that one arm gets right and the other gets wrong (step 10) say more than the two rates side by side. Lesson 3.1 measures how far one row's answer moves from run to run.

The new clerk at the HR helpdesk. A new clerk gets two kinds of help. For the hard question, "I am leaving with fifty days of leave: what do I get, and how long do I stay?", the supervisor says take a minute. The clerk works it out on a scratch pad, the pad goes in the bin, and the employee gets only the answer slip. The office pays for the clerk's minute whether or not anyone reads the pad, and a longer minute costs more: that is thinking, and its level. Or the supervisor says write your working on the slip. Now the employee reads the working, the slip is longer and costs more to write: that is prompted reasoning. At the sorting tray, where each letter goes to a counter, the supervisor does something else. Eight letters from last month are pinned above the tray, each stamped with the counter it went to, and the clerk sorts the next letter by its likeness to them: that is few-shot. To know whether any of it helps, the office manager does not ask the clerk. She runs the same files both ways and counts, and she knows that eleven files cannot tell a careful clerk from a lucky one.

Desks:
- handbook: the company's own HR handbook and policies: leave, notice periods, travel and expenses, payroll dates, IT and security rules, approvals, remote work

Rules:
- A question in the first person with no authority marker ("Can I carry forward leave?") is handbook.
- "Under the Act", "under the Code" or "under the law", or a named Act or Code, is statute.
- A question with both is two parts: route is the first desk, second_route the other.
- case_type is the kind of case when route or second_route is case, otherwise none.
- needs_calculation: the answer needs arithmetic on figures in the question.
- followup: the question only makes sense together with the previous question.

Definition

The Chat page's direct brain posts the question to /v1/stream with top_k 5. The stream retrieves and reranks as /v1/query does, then answers through generate_stream(): the same model, the same SYSTEM and the same thinking level, LOW, but no response schema, so the answer streams as plain text. What the page draws is the answer and its sources. The thinking is not in the stream, because the request names a level and asks for nothing back. It is in the bill. The stream's usage row carries tokens_out, which generator._usage() makes by adding the thought tokens to the visible ones, and the row's cost_usd prices all of it at the output rate.

def usage_of(r) -> dict:
    """What one reply billed, the thought tokens apart: the prompt (tokens_in, the cached ones among them), the visible
    output (candidates_token_count) and the thinking (thoughts_token_count, billed as output too), and why it stopped."""
    u = getattr(r, "usage_metadata", None)

    def n(key: str) -> int:
        return int(getattr(u, key, None) or 0)           # None from the SDK means "not this call", not 0 tokens

    cands = getattr(r, "candidates", None) or []
    fr = getattr(cands[0], "finish_reason", None) if cands else None
    finish = (getattr(fr, "name", None) or str(fr)) if fr is not None else ("UNKNOWN" if cands else "NO_CANDIDATES")
    return {"tokens_in": n("prompt_token_count"), "cached": n("cached_content_token_count"),
            "visible": n("candidates_token_count"), "thought": n("thoughts_token_count"), "finish": finish}
evals/prompt_bench.py - Recorder: every call sent at the level being benched, and keptread only
class Recorder:
    """generator._client for the bench's run. generate() reaches the model through _client_for(), which returns _client
    for a model name, so every call comes through generate_content() here: sent on with thinking_config at `level` and,
    when `temperature` is set, a temperature - everything else as generator._call built it - and kept in `calls` with
    the config as sent, the usage and the time it took."""

    def __init__(self, client, types_module):
        self.client, self.types = client, types_module
        self.level, self.temperature, self.calls = KIT_LEVEL, None, []

    @property
    def models(self):
        return self

    def configure(self, config):
        fields = {"thinking_config": self.types.ThinkingConfig(thinking_level=self.level)}
        if self.temperature is not None:
            fields["temperature"] = self.temperature
        if isinstance(config, dict):
            return {**config, **fields}
        return config.model_copy(update=fields)

    def generate_content(self, *, model, contents, config=None):
        config = self.configure(config)
        call = {"model": model, **sent(config)}
        self.calls.append(call)
        t0 = time.monotonic()
        try:
            r = self.client.models.generate_content(model=model, contents=contents, config=config)
        except Exception as e:
            call.update(ms=int((time.monotonic() - t0) * 1000), error=f"{type(e).__name__}: {str(e)[:160]}")
            raise
        call.update(ms=int((time.monotonic() - t0) * 1000), **usage_of(r))
        return r

def edit_system(system: str, add=(), drop=()) -> str:
    """SYSTEM with the rules numbered in `drop` (the kit's numbers) taken out and the lines in `add` appended,
    renumbered from 1. With neither, SYSTEM itself, byte for byte."""
    head, rules = rules_of(system)
    bad = sorted({n for n in drop if not 1 <= n <= len(rules)})
    if bad:
        raise ValueError(f"--drop-rule {bad[0]}: SYSTEM's rules are 1 to {len(rules)}")
    for text in add:
        if not text.strip() or "\n" in text:
            raise ValueError("--add-rule takes one line of text")
    kept = [r for i, r in enumerate(rules, 1) if i not in set(drop)] + [t.strip() for t in add]
    return "\n".join(head + [f"{i}. {r}" for i, r in enumerate(kept, 1)]) + "\n"


def arms(kit_system: str, add=(), drop=(), temperature: float | None = None, baseline: bool = True) -> list[dict]:
    """The prompts benched: the kit's (unless baseline is False) and, when anything is changed, one "edit" arm carrying
    every change - the rules edited (`changes`) and the temperature."""
    out = [{"name": "kit", "system": kit_system, "temperature": None, "changes": []}] if baseline else []
    changes = [f"rule {n} dropped" for n in sorted(set(drop))] + [f"rule added: {t.strip()}" for t in add]
    if changes or temperature is not None:
        out.append({"name": "edit", "system": edit_system(kit_system, add, drop), "temperature": temperature,
                    "changes": changes})
    return out

def bench(gen, rows: list[dict], pools: dict, arm_list: list[dict], levels: list[str], runs: int, model: str, judge,
          out=print) -> list[dict]:
    """Every row, arm, level and run, interleaved run by run so a drift on the lane falls on every arm alike. One record
    an answer: its verdict, the calls as the recorder saw them, the rupees, and - when it came back - the answer, its
    citations and each quote's check against the row's pool. generator.SYSTEM and generator._client are the kit's again
    when this returns, whatever happened."""
    kit_system, kit_client = gen.SYSTEM, gen._client
    recorder = Recorder(kit_client, gen.types)
    answers: list[dict] = []
    gen._client = recorder
    try:
        for run in range(1, runs + 1):
            for row in rows:
                pool = pools[row["id"]]
                chunks = chunks_of(pool)
                for arm in arm_list:
                    gen.SYSTEM, recorder.temperature = arm["system"], arm["temperature"]
                    for level in levels:
                        recorder.level, recorder.calls = level, []
                        status, body = answer_one(gen, row["question"], chunks, model)
                        v = judge(row, status, body)
                        rec = {"id": row["id"], "arm": arm["name"], "level": level, "run": run, "status": status,
                               "outcome": v["outcome"], "pass": bool(v["pass"]), "why": v["why"], "calls": recorder.calls}
                        rec["cost_inr"] = sum(call_inr(c) for c in rec["calls"])
                        if v["outcome"] == "ok":
                            rec.update(answerable=body["answerable"], confidence=body["confidence"],
                                       answer=body["answer"][:ANSWER_CHARS], model=body.get("model"),
                                       cites=[{"chunk_id": c.get("chunk_id"), "source_uri": c.get("source_uri"),
                                               "quote": c.get("quote"), "check": run_eval.quote_check(c, pool)}
                                              for c in body["citations"]])
                        else:
                            rec["error"] = body.get("error") if isinstance(body, dict) else None
                        answers.append(rec)
                        out(answer_line(rec))
    finally:
        gen.SYSTEM, gen._client = kit_system, kit_client
    return answers

@contextlib.contextmanager
def exemplars_in_prompt(desk_router, examples):
    """desk_router.PROMPT_EXEMPLARS swapped for `examples` for the duration, then put back whatever happens; None leaves
    it alone. desk_router imported the name from desk_routes and prompt() reads it there, so the L1 prompt is all that
    changes: desk_routes.PROMPT_EXEMPLARS, which prompt_groups() reads, is never touched."""
    if examples is None:
        yield
        return
    kept = desk_router.PROMPT_EXEMPLARS
    desk_router.PROMPT_EXEMPLARS = tuple(examples)
    try:
        yield
    finally:
        desk_router.PROMPT_EXEMPLARS = kept

def l1_alone(rows: list[dict], run: list[dict]) -> tuple[int, int, int]:
    """(right, asked, failed): L1's own route - decision["l1"], before the vote, the acceptance rules and the arbiter -
    against the row's acceptable routes, over the turns L1 was asked. A call that failed (decision["l1_error"]: a
    timeout, an error, an answer outside the schema, the turn's limits) is asked and wrong; a turn decided before L1
    (the gate, an anchor, single mode) is not counted."""
    by_id = {r["id"]: r for r in rows}
    asked = [x for x in run if x["decision"].get("l1") is not None or x["decision"].get("l1_error") is not None]
    right = sum(1 for x in asked if x["decision"].get("l1")
                and x["decision"]["l1"]["route"] in by_id[x["id"]]["acceptable_routes"])
    return right, len(asked), sum(1 for x in asked if x["decision"].get("l1") is None)

def wilson(k: int, n: int, z: float = Z95) -> tuple[float, float] | None:
    """The Wilson score interval for k of n. None for n = 0: no rows is no evidence, not 0% or 100%."""
    if n <= 0:
        return None
    p, z2 = k / n, z * z
    centre, margin = p + z2 / (2 * n), z * math.sqrt(p * (1 - p) / n + z2 / (4 * n * n))
    return max(0.0, (centre - margin) / (1 + z2 / n)), min(1.0, (centre + margin) / (1 + z2 / n))


def rate(k: int, n: int) -> str:
    """k/n = p% [lo%, hi%], the form every rate is printed in."""
    if n == 0:
        return "0/0 (no rows)"
    lo, hi = wilson(k, n)
    return f"{k}/{n} = {100 * k / n:.1f}% [{100 * lo:.1f}%, {100 * hi:.1f}%]"
