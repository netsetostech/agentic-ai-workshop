Level 3 · Re-embed

Re-issue the handbook as new bytes, and read the counts

Version 1's text behind one comment line: a new version for the ledger, the same text for the chunker.

Definition

The new rule needs the handbook to arrive again, and how it arrives decides what happens. The same bytes as version 1 would be a duplicate: the worker finds the claim it already holds and acks the event, cutting nothing. The bytes of any version retired in the last %%RETENTION%% days, revision 3 from lesson 1.6 or revision 2 from lessons 1.3, 6.3 and 11.4, would be the undo: the worker flips the retired rows back, still cut the old way, and embeds nothing. So the re-issue is version 1's text with one line in front of it, an HTML comment. The bytes are new, so the version key is new and the claim is won. And both twins drop a leading comment before they cut, the way they drop a mirror's provenance header, so the chunks are exactly version 1's text at %%NEW_PAIR%%: the counts measure the chunker and nothing else.
